# dsh-shadow-rewind

针对 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 的**会话级文件快照与回退 + AI 改动文件审查**插件（v0.2 起融合了 [dsh-file-review-tab](https://github.com/Lzh3070/dsh-file-review-tab) 的全部能力）。

两个互补的文件安全面：

| 面 | 机制 | 粒度 | 入口 |
|---|---|---|---|
| **会话回退** | 影子 jj 仓库整树快照 | 整个工作区 | 每条直发用户消息旁的「恢复到发送之前」按钮 |
| **文件审查** | 会话快照 + hunk 文本重放 | 改动块（hunk）/ 文件 / 轮 | 聊天轮尾卡片 + 侧边栏「文件审查」tab |

**核心设计：影子仓库平行线。** 工作区自身的任何 VCS（git / jj / 无）与本插件的影子 jj 仓库完全隔离——插件枚举文件只走目录扫描，快照字节只写入存储根下的隐藏 jj 仓库；恢复时只改写文件内容，绝不触碰工作区的 `.git`、`.jj`、HEAD、分支或提交。

```text
你的项目目录（随便怎么折腾）          插件存储根（$DSH_HOME/shadow-rewind/v1）
├── src/...                          └── workspaces/<key>/
├── .git/   ← 插件从不读写               ├── manifests/        恢复点清单
└── ...                                  │   ├── file-review/recorded/   Code Mode 录制（持久）
                                         └── shadow-repos/<key>/   影子 jj 仓库（快照字节）
```

## 一、会话回退（jj 影子仓库）

1. **自动检查点**：每轮对话在 Agent 第一步之前自动把工作区（可配置排除的目录除外）快照进影子 jj 仓库——每个检查点是一条显式 commit。
2. **回退入口**：每条直发用户消息下出现「恢复到发送之前」按钮；对话框预览将恢复的文件清单与快照时显式跳过的路径，并提供两种模式：
   - **恢复文件并从这里继续** —— 恢复文件后分叉新会话（原会话保留）；
   - **只恢复文件** —— 当前对话不动。
3. **恢复安全闸**（全部强制）：限时计划 + 确认串逐字回显 → 恢复前自动 rescue 备份 → 持久操作日志 → 事后哈希/权限验证；任何失败自动从备份回滚，绝不留半恢复状态。

快照是磁盘级目录扫描，因此无论文件是被 AI 的 write/edit 工具、命令行、git 操作还是外部编辑器修改的，都能恢复到检查点时的状态。超大、类型不支持或读取失败的路径会被**显式记录**（预览中展示「恢复不会碰它们」），而不是静默失败。

## 二、文件审查（自 dsh-file-review-tab 融合）

- **聊天轮尾卡片**：每轮结束后在对话里展示「Edited N files · +M −K」、可撤销/重做的整轮开关、文件 chips（点击深链进侧边栏）；
- **侧边栏「文件审查」tab**（需要 [dsh-better-sidebar](https://github.com/nicepkg/dsh-better-sidebar) ≥ 0.12，可选依赖）：逐轮分组的文件清单 + 行级红绿 diff、tab 徽章计数、在编辑器中打开、复制差异；
- **块级撤销/保留（本融合版增强）**：diff 视图里每个改动块（hunk）可勾选——只撤销/重做选中的块，未勾选的块原样保留；
- **每轮「快照恢复」按钮（本融合版增强）**：侧边栏每轮文件组头部可直接走 jj 影子快照把整个工作区恢复到该轮开始之前（复用会话回退的全部安全闸）；
- **Code Mode（run_code）录制**：嵌套派发的文件修改在宿主侧记录 before/after 并回放为 diff；**录制已持久化到磁盘（本融合版增强）**，宿主重启后依然可审查、可撤销；
- **最终回复文件提及**：注入系统提示引导模型用行内代码引用被修改文件，浏览器端点击即可打开；
- **终端删除识别**：解析成功的终端命令中的 rm 家族参数，以「已删除」条目展示（display-only）。

hunk 撤销的安全语义：逐 hunk 逆序文本回放 + 行锚点匹配 + 提交前字节级 CAS 复核 + 原子写 + 保留 CRLF 风格；外部编辑造成的失配会如实报告为「冲突」，绝不猜着改。

> **升级注意**：本插件已包含文件审查全部功能，请从 profile 中**移除 `dsh-file-review-tab`**，否则 Typert 命名空间、聊天轮尾链与侧边栏 tab 会双重注册。

## 三、多会话并行：两种恢复语义

同一个项目目录跑多个会话时，插件提供两种互斥的语义模式。侧边栏「文件审查」头部的开关随时切换（走 `/shadow-rewind/gate`，重启后回到 `writeGate` 配置初值）：

### 以当前为准（写入闸开启，默认）

**同一时刻只允许一个会话写入**，旁观者无关紧要、可被恢复波及：

- **所有权**：最近一次回合开始（= 你最近发消息）的会话拥有工作区，即「当前」；切换到另一个会话发消息的瞬间，所有权随之翻转——纯权限变更，无任何磁盘操作。
- **旁观者被降级为只读**：非当前会话的文件写入、bash/pwsh 终端、run_code、子代理派生一律被拒绝，模型会收到明确理由；读取、搜索、待办、提问等照常放行。
- **子代理继承**：当前会话的子代理经会话谱系（parentSession）继承写权利，其自身的回合开始也不会抢走所有权。
- **恢复整树放宽**：被拒绝写入的运行中会话不阻塞恢复——只有「你正在恢复的会话」和「当前所有者」还在运行时才阻塞。
- **中途切换**：关是软的（后续写入放行、恢复闸收紧）；开是硬的（旁观者的下一次写调用立即被拒）。所有权登记永远进行，开启时立刻有据可依。

### 对称（写入闸关闭）

**两边的工作都要保全**时用这个模式：

- **并行写入不限制**：所有会话都可写（拒绝裁决关闭；所有权登记照常，随时可切回）；
- **恢复按归属勾选**：预览里每条变更按检查点窗口标注归属——「只属于本会话 / 其它会话 / 双方都改过 / 来源不明」——默认只勾选**本会话**的路径，其它会话的工作不会被波及；也可以手动勾选任意路径一并恢复，勾「全部选中」即整树恢复；
- **运行中的会话阻塞恢复**：并行写入合法，恢复只在工作区空闲时执行；
- 归因来自影子仓库里所有会话的检查点时间线（检查点在回合开始捕获 → 窗口 [S_j, S_{j+1}) 的写者就是 S_j 的会话）。标签是建议而非裁决——勾选权在用户，标签错了最多误导、不破坏数据；双方都改过的路径默认排除，由你决定是否一并还原。

**边界**：两种模式的闸与归因都只作用于本插件可见的 DSH 工具调用与影子仓库快照——外部编辑器、IDE 与系统进程不受限；白名单内的只读工具可用 `writeGateAllow` 扩充。

## 安装

```sh
pnpm install
pnpm run check          # 构建 + 测试（jj 可用时自动加测影子后端）
dsh plugin --profile web add dsh-shadow-rewind
```

依赖：Node ≥ 22.19；`jj` CLI **可选**——缺失时自动检查点降级为内置 blob 存储，功能不中断（启动日志会提示降级）。

## 配置（cordis.patch.yml）

```yaml
- id: ui-deliverables
  disabled: true                   # 内置产物卡片由本插件的轮尾卡片接管

- insert:
    - id: shadow-rewind
      name: 'dsh-shadow-rewind'
      config:
        turnCheckpointMode: jj          # jj（默认）/ legacy / off
        excludePatterns:                # 工作区相对 glob；字面路径=任意层级同名目录
          - .git
          - .jj
          - node_modules
          - dist
        maxFileBytes: 16777216          # 超限文件跳过并显式记录
        maxFiles: 20000
        maxSnapshotBytes: 536870912
        maxTurnCheckpointsPerSession: 30
        maxRestorePoints: 50
        planTtlMs: 900000
        turnCheckpointTimeoutMs: 5000
        turnCheckpointMaxNewBytes: 33554432
        turnCheckpointTrust: fast       # fast=stat 缓存增量；strict=全量重读
        writeGate: true                 # 恢复语义模式：true=以当前为准（默认），false=对称；侧边栏可运行时切换
        writeGateAllow: []              # 写入闸在只读白名单外额外放行的工具名
```

HTTP 端点为同源 `/shadow-rewind`（仅接受回环请求）：`GET ?sessionId&messageSeq`（消息回退预览）与 `GET ?sessionId&turn`（按轮快照预览），`GET ?...&paths=[...]` 铸造对称模式的勾选子集计划，`POST` 携带计划 id + 确认串执行；`/shadow-rewind/gate` 查询/翻转语义模式。浏览器半边随包分发。

## 测试

`pnpm test` 使用真实临时目录跑完整链路：

- 引擎：修改/删除/新增文件的恢复、排除规则、超大文件跳过、计划过期拒绝、删除确认闸、无变更短路、stat 缓存增量；宿主机装有 `jj` 时自动加测影子后端往返；
- 文件审查：hunk 子集撤销语义、Code Mode 录制的持久化往返与损坏文件自愈；
- 写入闸：所有权登记与翻转、按工具拒绝/放行、子代理谱系继承、所有者消失兜底、恢复占用分诊、运行时开关；
- 对称模式：检查点窗口归因（目标/其它会话/双方/未知）、勾选式子集恢复只还原勾选路径、未知路径拒绝。

## 边界（当前版本）

- 恢复的是**文件内容**：不回滚任何 VCS 历史（工作区 git 的提交不受影响）；
- 空目录结构不单独追踪（按需在恢复时重建/回收）；
- 跨机共享存储未设计（锁判活按单机 pid）；
- Code Mode 录制按结果形状 `{path, before, after}` 识别嵌套修改，返回该形状的非文件工具会被误录（与原 dsh-file-review-tab 一致）。
