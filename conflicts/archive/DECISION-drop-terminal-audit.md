# 决策记录：放弃终端写盘的命令级监听（2026-09）

> 决定：AI 在终端（bash / PowerShell / git 等命令工具）中对文件的更改不再做
> 命令级监听与归因，**只靠 jj 检查点轮 diff 兜底**——终端写盘仍然可见、
> 可撤销（fs 条目照旧），但不再回答「是哪条命令写的」。
>
> 本文档记录该决定的波及面：哪些冲突随之消失、哪些原样保留、删什么、
> 留什么新决策点。各组方案的详细取舍仍见 A–K 各文档。

## 明确保留的东西（不要误删）

- **写入闸对终端工具调用的裁决**：这是执行拦截（非所有者的终端调用被拒），
  不是写盘监听。`write-gate.ts` 原样保留。
- **轮起/轮末检查点**：轮末精确冻结照旧，它是 fs diff 的边界。
- **fs 条目的可见与可撤销**：终端写盘经轮 diff 仍以 added/modified/deleted/
  mode-changed/空目录条目出现，file-review apply 照常撤销（不需要知道写者）。
- **多会话的快照网格归属**：对称模式的归属标签、闸开的 `owner==='target'`
  过滤走检查点区间网格（`listSnapshotsAfter`），**不依赖命令窗口**，保留。

## 原样保留、仍需处理的

- **功能级坏点（最优先）**：F-1（typert schema 缺字段，目录/纯 chmod 撤销
  线上不可达）、G-1（对称模式勾选恢复死路径）。两者与终端监听无关。
- **A-2 挂靠**：仍需要——工具写入仍被工具视图和 fs diff 两套数学各算一遍。
  变小了（无窗口层），但结构性收敛本身不因本决定而免除。
- **H 组几乎全部**：H-4（run_code CRLF 永久 conflict）、H-5/6/9 极小批、
  H-3 三套 CAS、H-7/H-8——fs 条目撤销状态机原样在跑。
- **E 组**：run_code 是 Code Mode 工具不是终端，重复记账照旧。
- **B-1、D-1、I-1 剩余（网格归属在闸开时仍是静默裁决）/I-4/I-6/I-7/I-8、
  J 独立包（路径归一/CRLF 口径/ensuredFs/空文件/dedupe）、K 组**：与终端
  监听无关。

## 如实接受的损失

1. 「哪条命令写的」命令级归因与 fs 条目上的命令意图摘要消失
   （时间线 trace 端点的意图标签来自工具事件解析，保留）。
2. live 轮的终端删除从「词法即时预览」退为「live-tail fs diff 兜底」，
   有 warm 轮询的秒级延迟；词法管线在 fs 证据到来前的占位价值放弃。
3. `commandWindow*` 四个配置键、README 第三节「终端写盘审计」叙事需改写
   （「检查点窗口归属对比」→「检查点轮 diff 兜底，归属只到会话级」）。

## 遗留的新决策点

1. **闸开 fs 过滤的最终语义（I-1 剩余）**：网格归属在闸开时仍是静默裁决
   （64 快照上限塌缩时会误剔本会话路径）。自用建议：维持剔除但 catch 分支
   统一为剔除（一行），degraded 标注缓做。
2. **意图标签去留**：fs-changes 条目的意图摘要随窗口消失后，是否把 trace
   端点的意图标签（工具事件解析）挪来补——建议不做，先看裸清单够不够用。
