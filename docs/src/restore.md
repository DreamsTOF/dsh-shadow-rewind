# 恢复管线与撤销

这是插件安全性质最重的一条路径。下面的时序图覆盖「预览 → 计划 → 执行（rescue + 验证）→ 撤销」的完整交互，以及失败时的自动回滚。

## 预览：两种寻址，同一套安全语义

- **消息寻址**（`?sessionId&messageSeq`）：消息旁「恢复到发送之前」按钮。`messageTarget`（`src/host/session-resolve.ts`）只允许回退**回合的第一条直发用户消息**（插件注入等来源不可回退），并校验所选消息仍在其记录的回合内——这是检查点粒度（轮起）决定的语义边界，不是流程锁。
- **轮寻址**（`?sessionId&turn`）：侧边栏「从快照恢复此轮」与轮尾卡片「回滚到上一轮检查点」。

两种寻址都解析到同一条轮起检查点。fork 产物（子会话）没有自己的检查点时沿父链继承，且只有回合起点落在 seed 范围内（fork 之前发生的回合）才允许继承，继承检查点的 `turnStartSeq` 必须与本会话回合起点一致（`resolveTurnCheckpoint`）——谱系环、父元数据不完整一律 `PLAN_STALE`。

预览响应里：变更清单分页（初始 8 条）、逐条归属标签、**跳过项逐条透传 `{path, reason}`**——用户必须看到哪些文件不在快照内、为什么，而不是只给一个数字。

## 计划：同源核对 + 逐路径复核（EXPECTED-DESIGN 1.4 落地后）

`planRestore`（`src/engine.ts`）铸出一份数据库外的内存计划：

1. `expectedCurrentTreeHash` 不符 → `PLAN_STALE`（检查之后工作区又变了）——检测保留（#5）；
2. **快照时显式跳过的路径绝不允许构成恢复动作**——否则「新增的大文件」会在恢复时被误删（计划内 skippedSet 过滤）；
3. 对称模式勾选子集时，未知路径立即拒绝（防止客户端拿错版本的清单拼出半个计划）；
4. 每条待恢复路径记录 `expected`（计划时的磁盘条目），供执行前复核；
5. **确认串已废除（#2）**——「确认」由 GUI 弹窗承担；**TTL 过期只作软警告（#1）**——过期计划仍可执行，只有远超 24h 保留窗口的陈旧计划才从内存淘汰。

## 执行：rescue → 恢复 → 验证 → 失败自动回滚

`applyRestore`（`src/engine.ts`）按顺序执行：

1. **计划存在**（`applying` 集合防重入保留，#8）；
2. **计划复核** `assertPlanFresh`：每条路径的当前内容必须仍与计划时一致——检测保留（#4），失配拒绝（防止恢复到错误时点）；
3. **rescue 备份**：恢复前把当前状态捕获为一个 rescue 恢复点（独立配额），失败的回滚与「后悔药」都靠它；
4. **会话绑定不匹配只记软警告（#3）**：结果里的 `warnings` 字段如实呈现，不阻断执行。

真正的写盘在 `restorePaths`：

- 先删「快照中不存在」的路径（恢复新建文件的反面），**深层优先**，逐个收空父目录；
- 再恢复「快照中存在」的路径，**浅层优先**（父目录先就位）；
- 每个文件读回快照字节后先验 `sha256 == entry.blob`，不符抛 `BLOB_CORRUPT`，然后原子替换（`replaceRegularFile`）；
- 符号链接重建链接实体、空目录按记录的权限位重建；
- 快照时显式跳过的路径永远不该出现在删除集合里——即使上层计划已过滤，这里再兜一次底。

写完不是结束：`verifyRestored` 对每个路径重新落盘读取，校验存在性、类型、权限位（POSIX）与内容哈希。

**失败路径（两态翻转）**：主恢复失败 → 立即从 rescue 点回滚全部涉及路径（回滚不走 expected 复核——目标就是把状态打回 rescue 时点）→ 成功即停在状态 A；回滚也失败 → `RECOVERY_REQUIRED` 错误如实抛出，rescue 点仍在，翻转可幂等重跑。**持久操作日志状态机（running/interrupted/recovery-required）已废除（#11）**——磁盘上不再维护中间态，崩溃后用户从 rescue 点重跑即可收敛。

「恢复文件并从这里继续」的会话分叉在文件恢复成功**之后**执行（`sessionController.create/fork`）；分叉失败时把文件滚回操作前，绝不留半完成状态——补偿走 `skipUndoRecord`（补偿本身也是 applyRestore，不再写 undo 单槽）。

## 撤销最近一次恢复：两段式 + 三选项弹窗（EXPECTED-DESIGN 1.2）

`undoLastRestore` 支持两种模式：

- **`mode: 'probe'`（只读探查）**：逐路径 CAS 只读比对，返回 `{clean, conflicted}`——客户端据此弹三选项对话框，不动磁盘；
- **`mode: 'apply'`（执行撤销）**：
  - **逐路径 CAS**：当前磁盘条目必须仍等于「恢复后」的状态（`entriesEqual` 内容寻址等价），失配路径跳过并如实报告，绝不猜着回退；全部失配 → 409（`UNDO_CONFLICT`）；
  - **`force: true`（用户在弹窗显式授权）**：对指定路径绕过 CAS，直接从 rescue 清单回写——覆盖恢复之后的用户修改；before=null 的路径（恢复新建的）强制撤销即删除，即使被改过——这是「绝不删除」的第二处用户授权例外；
  - **`paths` 子集**：二次回滚按清单来；成功路径从 undo 记录中收缩，记录清空才销毁——部分成功永远可重试；
  - 撤销动作复用 rescue 清单的 `restorePaths`（全套安全路径：围栏断言、原子写、空目录回收、非空拒删、跳过项不删）。

## 与多会话的关系

恢复预览按检查点窗口给出归属标签（`listSnapshotsAfter` + `attributePaths`），对称模式勾选式子集恢复（`paths=[...]` 铸造子集计划）。写入闸移除后（见[概述](overview.md)），恢复不再等待运行中的会话——多主路径仍按网格归属保守剔除出单会话视图，整树恢复可还原一切。
