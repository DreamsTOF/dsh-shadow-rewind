# dsh-shadow-rewind 操作与预期手册

> 逐功能写明：**入口 → 操作 → 预期**（可核验的行为）→ **异常与边界**。
> 功能总览见 `docs/features.md`；条目编号与该文件一致，便于对照核验。
> 通用前置：插件已装配（`ctx.shadowRewind` 就绪，启动日志输出「就绪；存储=… 后端=…」）。

---

## 1. 会话回退面（消息级回退）

### 1.1 消息旁「恢复到发送之前」按钮

- **入口**：聊天区每条**直发用户消息**的 hover 操作行（copy/branch 图标旁多一个 ↶ 图标）。
- **操作**：把鼠标悬停在任意一条你自己发出的消息上，点击 ↶。
- **预期**：
  - 弹出「恢复到发送这条消息之前」对话框（居中模态，Esc / 点遮罩 / ✕ 关闭）。
  - 消息行 DOM 形状与预期不符时**不挂按钮**（绝不误挂到别的气泡上）。
- **异常与边界**：
  - 插件注入的非直发消息（系统注入）没有按钮——刻意设计。
  - 按钮点击绝不改变聊天滚动位置或触发消息点击事件（stopPropagation）。

### 1.2 恢复预览对话框（对称模式）

- **入口**：1.1 的按钮。
- **操作**：等待预览加载（GET `/shadow-rewind?sessionId&messageSeq`）。
- **预期**：
  - 列出从该消息起到现在，工作区里**仍可回退**的全部文件变更（修改/新增/删除分类展示，+/- 行数）。
  - 只属于本会话的路径默认勾选；其它会话/多方的路径须显式勾选（归属标签可见）。
  - 清单超过一页时自动分页拉全；有「展开全部」能力。
  - 终端写盘类变更（PowerShell 等）作为 fs 条目单独归类展示。
  - 快照跳过项逐条显示 `{path, reason}`（如 `too-large`）。
  - 默认模式 `both`；可切 `code`。
- **异常与边界**：
  - 预览期间磁盘又变了 → 显示 PLAN_STALE 与「重新检查」按钮；重新加载后恢复可用。
  - 该消息不是回合的第一条直发消息 → 报「只支持回退回合的第一条用户消息」。
  - 没有任何变更 → 提示与恢复点一致，无可恢复项。

### 1.3 执行恢复（mode both / code）

- **操作**：在对话框里确认勾选后点击「恢复」。
- **预期（both）**：
  1. 勾选路径的文件回到该消息发出之前的状态（修改被还原、之后新建的文件被删除）；
  2. 自动创建一个新对话并打开，被撤回的消息文本回填到输入框（草稿）；
  3. 对话框显示「项目文件已恢复，并已创建新对话」后自动关闭。
- **预期（code）**：
  - 只恢复文件；当前对话保持不变，显示「项目文件已恢复；当前对话保持不变」。
- **异常与边界**：
  - 新会话创建失败 → 文件自动滚回操作前，报「文件已自动还原；新会话创建失败」；
  - 恢复本身失败 → 自动从 rescue 备份回滚，报 RESTORE_FAILED_ROLLED_BACK；
  - 回滚也失败 → RECOVERY_REQUIRED，并给出 rescue 点 id 供手工恢复。

### 1.4 撤销本次恢复

- **入口**：恢复完成后对话框上的「撤销本次恢复」（进程内单次 undo）。
- **操作**：点击撤销。
- **预期**：
  - 先做只读 probe：逐路径比对当前磁盘是否仍等于「恢复完成瞬间」的状态；
  - 全部干净 → 直接撤销，每个路径回到恢复前的状态；
  - 有路径在恢复后又被修改 → 弹三选项：**拒绝** / **全部回滚**（覆盖那些修改）/ **只回滚正常部分**；
  - 撤销后 live 条的条目随之还原（遮蔽标记弹出）。
- **异常与边界**：
  - 进程重启后不可撤销（提示可从 rescue 点手工恢复）；被跳过路径可再次点击强制回滚。

## 2. 回滚数据来源（自动，无需操作；核验观察点）

### 2.1 BEFORE 捕获（主路）

- **入口**：无 UI；AI 每次调用 `write` / `edit` / `str_replace_editor`（编辑器限 create / str_replace / insert）时自动触发。
- **预期（自动行为）**：
  - 写盘**前**，目标文件全文被记入 BEFORE 日志，锚定到本回合最新的 user message seq；
  - 创建文件（写盘前不存在）记录为「创建」——回滚语义是删除；
  - 工具执行失败不记录（磁盘没变）；子代理会话不记录；工作区外路径不记录；
  - 每条用户消息落盘时，重查全部被跟踪文件：外部编辑/删除（含你自己手动改）补一条 BEFORE。
- **核验方法**：让 AI 改一个文件后，检查 `~/.dsh/shadow-rewind/v1/workspaces/<key>/before-journal/<会话>/<anchorSeq>/` 下出现 JSON 记录（含 `content` 全文）。
- **边界**：超过 `maxFileBytes`（16MB）的文件不入日志；目录/符号链接不入日志。

### 2.2 消息检查点兜底（kind `message`，partial）

- **入口**：无 UI；消息回退时若该回合没有影子检查点，自动从 BEFORE 日志物化。
- **预期**：
  - 「没料可回」的场景（检查点被关/失败/被修剪）仍能回滚 AI 改过的文件；
  - 未被 BEFORE 覆盖的文件**绝不会被误删**（partial 语义）；
  - 工具创建过的文件按「恢复即删除」处理。
- **边界**：终端写盘（非工具）且无检查点时，这部分仍回不到（BEFORE 盲区）——预览里看不到它们。

### 2.3 影子整树快照（轮起 / 轮末自动检查点）

- **入口**：无 UI；每个 agent 回合开始前 / 结束时自动捕获整树。
- **预期**：
  - 检查点在位时，消息回退/轮恢复优先用全树检查点（含终端写盘，语义最全）；
  - jj CLI 在位 → 后端 `jj`（影子仓库）；不在位 → 自动降级 `sqlite` 并在启动日志注明；
  - 每会话每相位保留最近 30 个检查点，旧的自动修剪。
- **核验方法**：`/shadow-diff` 或管理面板能看到轮检查点列表；`turnCheckpointMode: 'off'` 时完全不捕获（此时 BEFORE 日志兜底接管）。

## 3. 文件审查面

### 3.1 live 条（会话累计变更条）

- **入口**：输入框上方常驻条（`conversation.input.dock`），会话有任何仍生效的文件改动时出现。
- **操作与预期**：
  - **读数**：标题「已更改 N 个文件」+ 总 +/- 行数；N = 当前仍生效的改动文件数（5 轮改 10 个 → 10；回滚 2 轮撤销 5 个 → 5）。
  - **滚动**：最多同时露 8 行，超出滚动条。
  - **悬停**：任意行悬停 ~300ms 弹出对齐输入框宽度的 diff 浮层（fs 条目首次悬停时补拉全文）。
  - **行内撤销/重做**：行尾 ↶/↺ 按钮，单击把该文件的全部 hunks 撤销（或重做）；成功显示绿色提示，行上出现「已撤销」徽标且按钮翻转为重做；失败显示红色原因（冲突时提示去审查界面）。
  - **点击行 / 头部「审查」按钮**：打开全屏审查界面；点行时自动展开该文件的 diff。
  - **宽度**：与输入对话框对齐（同宿主 dock 几何变量）。
- **异常与边界**：
  - 回滚后条目按「恢复屏障」扣减；屏障后再编辑同文件会重新出现；
  - fs 占位行（终端写盘）没有全文时不弹出浮层；
  - 无任何改动时整条不渲染。

### 3.2 文件审查全屏界面（AuditOverlay）

- **入口**：live 条头部「审查」按钮，或点 live 条任意行。
- **操作与预期**：
  - 逐轮列出本会话的全部文件变更（轮分组、组内红/绿 diff、归属徽标：本会话/他会话/多方/未知）；
  - **hunk 级**：勾选部分 hunk 后按文件/按轮撤销或重新应用；冲突文件先过三选项弹窗；
  - **按轮快照恢复**：轮头「从快照恢复」→ 确认对话框（警告整树恢复范围）→ 确认后整树回到该轮开始之前；
  - 文件级时间线：单个文件跨轮的改动历史；
  - 刷新按钮强制重查宿主状态；Esc / 遮罩 / ✕ 关闭。
- **同步**：在审查界面做的撤销/重做，live 条对应行立即翻转（反之亦然）。
- **异常与边界**：侧边栏不再有此 tab（已移除）；审查界面为独立模态窗口。

### 3.3 行内文件提及

- **入口**：AI 最终回复里的行内代码文件名。
- **预期**：可点击打开对应文件；来源是工具产出的确定性路径，与轮尾产出同一套词汇。

## 4. pending 消息撤回

- **入口**：聊天输入框上方**待执行（steering）气泡**的操作行里的撤回图标。
- **操作**：点撤回图标 → 确认对话框（显示被撤回文本与「之后的排队消息会一并撤回」）→ 点「撤回」。
- **预期**：
  - 目标气泡及其后全部排队 steering 气泡从队列移除（宿主 `updateQueue remove`，不是 DOM 魔改）；
  - 若输入框为空，被撤回文本回填输入框（有草稿则不动）；
  - 若消息恰好在确认瞬间被运行中的回合领取，remove 静默失败，不报错。
- **边界**：子代理会话的 pending 行不出现撤回按钮；按钮与气泡文本严格匹配才挂载。

## 5. 命令面

### 5.1 /shadow-diff

- **操作**：会话内输入 `/shadow-diff <参数>`（两检查点对比）。
- **预期**：输出两快照的逐文件差异摘要（含 +/− 行数，内容按需懒取）。

### 5.2 /shadow-undo

- **操作**：会话内输入 `/shadow-undo`。
- **预期**：列出/操作恢复点（撤销最近一次恢复等），与 GUI 的单次撤销同一套安全闸。

## 6. 设置（设置 → 插件 → shadow-rewind 卡片）

| 配置 | 操作 | 预期 |
|---|---|---|
| `maxRestorePoints` | 改数值保存 | 手动恢复点配额即时生效；rescue 不占额 |
| `maxTurnCheckpointsPerSession` | 改数值保存 | 每会话每相位保留窗口变化，超出的下次修剪 |
| `maxFiles` / `maxFileBytes` / `maxSnapshotBytes` | 改数值保存 | 捕获闸变化；超限文件进 skippedPaths 且恢复永不碰它 |
| `planTtlMs` | 改数值保存 | 计划过期仅软警告（expired 标记），不拒绝执行 |
| `turnCheckpointMode` | jj / sqlite / off | **需重启**；off = 停止轮检查点（BEFORE 日志兜底仍在） |
| `turnCheckpointTimeoutMs` / `MaxNewBytes` | 改数值保存 | 单次检查点超时/字节闸；超限跳过并留持久跳过记录 |
| `turnCheckpointTrust` | fast / strict | strict = 每次捕获全量读回验证 |
| `excludePatterns` | 改列表保存 | 命中目录整棵不入快照、不入恢复范围 |
| `storageDir` | 只读 | 启动级，热更被拒绝 |

- **预期**：卡片保存后引擎热更（除启动级字段）；`GET /shadow-rewind/config` 与卡片一致。

## 7. 管理与诊断

- **管理面板**（GET/POST `/shadow-rewind/manage`）：恢复点树、各恢复点磁盘占用、单点删除（被 undo 引用的 rescue 拒删）、「立即 GC」。
- **状态诊断**（GET `/shadow-rewind/status`）：最近 20 条错误（相邻重复合并计数 + 环境分类 hint）、后端健康度；POST `{op:'clear'}` 清空。
- **核验方法**：浏览器直接访问 `http://127.0.0.1:<port>/shadow-rewind/status`。

## 8. 端到端核验剧本（建议按序执行）

1. **准备**：新建会话，工作区放 `a.txt`（v1）。
2. **捕获**：让 AI 用 edit 把 `a.txt` 改成 v2，再手动用记事本改一处（外部编辑）。
   - 预期：before-journal 出现 anchor 记录；下一条消息落盘时外部编辑被补录。
3. **live 条**：输入框上方出现「已更改 1 个文件」，行内 +/- 与 diff 浮层正确。
4. **行内撤销**：点 ↶ → 文件回到 v2 之前（AI 改动被撤）；再点 ↺ → 回到 v2。
5. **回退**：点该消息旁 ↶ → 预览列出变更 → `both` 执行 → 文件回到最初、新会话打开。
6. **撤销恢复**：恢复后点「撤销本次恢复」→ 文件回到恢复前状态。
7. **检查点兜底**：设置 `turnCheckpointMode: 'off'` 并重启，重复 2/3/5 → 消息回退仍可用（消息检查点兜底），且未捕获文件原样保留。
8. **pending**：回合运行中连发两条消息 → 气泡上点撤回 → 确认 → 气泡消失、文本回填。
9. **审查界面**：live 条「审查」→ 逐轮 diff 展开、hunk 撤销、与 live 条状态双向同步。
