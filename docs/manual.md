# dsh-shadow-rewind 操作与预期手册

> 逐功能写明：**入口 → 操作 → 预期**（可核验的行为）→ **异常与边界**。
> 功能总览见 `docs/features.md`。通用前置：插件已装配（`ctx.shadowRewind` 就绪，
> 启动日志输出「就绪；存储=… 后端=…」）。

---

## 1. 会话回退面

### 1.1 消息旁「恢复到发送之前」按钮

- **入口**：聊天区每条**直发用户消息**的 hover 操作行（copy/branch 图标旁多一个 ↶ 图标）。
- **操作**：把鼠标悬停在任意一条你自己发出的消息上，点击 ↶。
- **预期**：弹出「恢复到发送这条消息之前」对话框（居中模态，Esc / 点遮罩 / ✕ 关闭）。
- **异常与边界**：消息行 DOM 形状与预期不符时**不挂按钮**（绝不误挂到别的气泡上）；插件注入的非直发消息没有按钮。

### 1.2 恢复预览对话框

- **操作**：等待预览加载（GET `/shadow-rewind?sessionId&messageSeq`）。
- **预期**：
  - 列出该检查点与**当前磁盘**的全部差异——即恢复会改动的每一个文件（修改/新增/删除），逐文件带服务端算好的净 `+/−` 行数；
  - 顶部说明：「恢复按检查点整树进行：这之后的一切写盘都会被丢弃——包括终端/外部进程的改动与你自己手动做的修改」；
  - 快照跳过项逐条显示 `{path, reason}`（如 `too-large`）；
  - 点任意文件行 → 打开审查界面并深链展开该文件的完整 diff。
- **异常与边界**：
  - 预览期间磁盘又变了 → 显示「项目文件在检查后又发生了变化」与「重新检查」；
  - 该消息不是回合的第一条直发消息 → 报「只支持回退回合的第一条用户消息」；
  - 该回合没有可用检查点 → 如实提示「没有保存这条消息发送之前的文件」（没有部分树兜底）；
  - 没有任何变更 → 提示工作区已是该时点状态。

### 1.3 执行回退

- **操作**：点「就地回退」（消息入口）或「恢复文件」（轮入口）。
- **预期（消息入口）**：
  1. 工作区**整树**恢复到该消息所属回合的轮起检查点（丢弃其后一切写盘）；
  2. 宿主向本会话日志追加空内容**遮蔽标记**（`surfaceOp.replace` + `sourceEventSeqs`）；
  3. 客户端把 [目标消息 … 遮蔽标记] 区间的消息行隐藏（`data-dsh-rewind-hidden`）；刷新/换页后从 chat 快照重算，幂等；
  4. 目标消息文本在**输入框为空**时回填，可修改后重发（有草稿绝不动）。
- **预期（轮入口，审查界面「快照恢复」）**：只恢复文件，当前对话保持不变。
- **异常与边界**：
  - 文件恢复失败 → 自动从 rescue 备份回滚（RESTORE_FAILED_ROLLED_BACK），绝不留半恢复状态；
  - 回滚也失败 → RECOVERY_REQUIRED，并给出 rescue 点 id 供手工恢复；
  - 宿主不支持遮蔽面 → 显示错误原因，文件状态不受影响；运行中的回合会被先打断。

### 1.4 撤销本次恢复

- **入口**：恢复完成后对话框上的「撤销本次恢复」（进程内 undo 栈，重启失效）。
- **操作**：点击撤销。
- **预期**：
  - 先做只读 probe：逐路径比对当前磁盘是否仍等于「恢复完成瞬间」的状态；
  - 全部干净 → 直接撤销，每个路径回到恢复前的状态；
  - 有路径在恢复后又被修改 → 弹三选项：**拒绝** / **全部回滚**（覆盖那些修改）/ **只回滚正常部分**；
  - 撤销后 live 条的条目随之还原（遮蔽标记弹出）。
- **边界**：被跳过路径可再次点击强制回滚；其它会话发起的恢复被撤销时，本会话不弹自己的遮蔽层。

## 2. 回滚数据来源（自动，无需操作；核验观察点）

### 2.1 影子整树快照（唯一数据源）

- **入口**：无 UI；每个 agent 回合开始前 / 结束时自动捕获整树。
- **预期**：
  - 每轮的文件变更 = diff(轮起检查点, 轮末检查点)——工具写盘、Code Mode 嵌套派发、终端命令、外部进程改动**一视同仁**；
  - jj CLI 在位 → 后端 `jj`（影子仓库）；不在位 → 自动降级 `sqlite` 并在启动日志注明；
  - 每会话每相位保留最近 30 个检查点，旧的自动修剪；rescue 点独立配额。
- **核验方法**：live 条 / 审查界面 / `/shadow-diff` 或管理面板看到逐轮清单；`turnCheckpointMode: 'off'` 时完全不捕获（此时回退对话框如实提示「没有快照」）。
- **边界**：排除清单（`.git` / `node_modules` / 构建产物等）内的写盘完全不可见；超限文件显式跳过。

## 3. 文件审查面

### 3.1 live 条（会话累计变更条）

- **入口**：输入框上方常驻条（`conversation.input.dock`），会话有任何仍生效的文件改动时出现。
- **操作与预期**：
  - **读数**：标题「已更改 N 个文件」+ 总净 +/- 行数（服务端按检查点算好的跨轮净变化；新建后又删除的路径不出现）；
  - **滚动**：最多同时露 8 行，超出滚动条；
  - **悬停**：任意行悬停 ~300ms 弹出对齐输入框宽度的 diff 浮层（全文按检查点懒取并记忆）；
  - **行内撤销/重做**：行尾 ↶/↺ 按钮，单击把该文件的全部 hunks 撤销（或重做）；成功显示绿色提示，行上出现「已撤销」徽标且按钮翻转为重做；失败显示红色原因（冲突时提示去审查界面）；
  - **点击行 / 头部「审查」按钮**：打开全屏审查界面；点行时自动展开该文件的 diff；
  - **徽标**：删除 / 目录 / 已撤销 / 归属（本会话/其它会话/双方/未知，仅信息展示）。
- **异常与边界**：
  - 回滚后条目按「恢复屏障」扣减（整树恢复 = 全部遮蔽）；屏障后再编辑同文件会重新出现；
  - 无任何改动时整条不渲染。

### 3.2 文件审查全屏界面（AuditOverlay）

- **入口**：live 条头部「审查」按钮，或点 live 条任意行。
- **操作与预期**：
  - 逐轮列出本会话的全部文件变更（轮分组、组内红/绿 diff、归属徽标）；
  - **hunk 级**：勾选部分 hunk 后按文件/按轮撤销或重新应用；冲突文件先过三选项弹窗；
  - **按轮快照恢复**：轮头「快照恢复」→ 确认对话框（警告整树恢复范围）→ 确认后整树回到该轮开始之前；
  - 文件级时间线：单个文件跨轮的改动历史；
  - 刷新按钮强制重查宿主状态；Esc / 遮罩 / ✕ 关闭。
- **同步**：审查界面做的撤销/重做，live 条对应行立即翻转（反之亦然）。

### 3.3 行内文件提及

- **入口**：AI 最终回复里的行内代码文件名。
- **预期**：可点击打开对应文件；路径词汇来自该轮工具结果（仅用于链接解析）。

## 4. pending 消息撤回

- **入口**：聊天输入框上方**待执行（steering）气泡**的操作行里的撤回图标。
- **操作**：点撤回图标 → 确认对话框（显示被撤回文本与「之后的排队消息会一并撤回」）→ 点「撤回」。
- **预期**：
  - 目标气泡及其后全部排队 steering 气泡从队列移除（宿主 `updateQueue remove`，不是 DOM 魔改）；
  - 若输入框为空，被撤回文本回填输入框（有草稿则不动）；
  - 若消息恰好在确认瞬间被运行中的回合领取，remove 静默失败，不报错。
- **边界**：子代理会话的 pending 行不出现撤回按钮；按钮与气泡文本严格匹配才挂载。

## 5. 命令面

### 5.1 /shadow-diff

- **操作**：会话内输入 `/shadow-diff <参数>`。
- **预期**：输出两时间节点的逐文件差异摘要（含 +/− 行数，内容按需懒取）。参数：轮号（单轮 = 轮起→轮末配对）、检查点 id（`rp_…`）、轨迹节点（`trace:序号`）；快照与轨迹不可混用。

### 5.2 就地回退命令

- ❌ 已移除：`/shadow-inplace`、`/rewind`、`/shadow-undo` 均不再注册——就地回退走消息旁 ↶ 弹窗，撤销走弹窗内「撤销本次恢复」。

## 6. 设置（设置 → 插件 → shadow-rewind 卡片）

| 配置 | 操作 | 预期 |
|---|---|---|
| `maxRestorePoints` | 改数值保存 | 手动恢复点配额即时生效；rescue 不占额 |
| `maxTurnCheckpointsPerSession` | 改数值保存 | 每会话**每相位**保留窗口变化，超出的下次修剪 |
| `maxFiles` / `maxFileBytes` / `maxSnapshotBytes` | 改数值保存 | 捕获闸变化；超限文件进 skippedPaths 且恢复永不碰它 |
| `turnCheckpointMode` | jj / sqlite / off | **需重启**；off = 停止轮检查点（回退入口如实提示没有快照） |
| `turnCheckpointTimeoutMs` / `turnCheckpointMaxNewBytes` | 改数值保存 | 单次检查点超时/字节闸；超限跳过并留持久跳过记录 |
| `turnCheckpointTrust` | fast / strict | strict = 每次捕获全量读回验证 |
| `excludePatterns` | 改列表保存 | 命中目录整棵不入快照、不入恢复范围 |
| `storageDir` | 只读 | 启动级，热更被拒绝 |

- **预期**：卡片保存后引擎热更（除启动级字段）；`GET /shadow-rewind/config` 与卡片一致。

## 7. 管理与诊断

- **管理面板**（GET/POST `/shadow-rewind/manage`）：恢复点树、各恢复点磁盘占用、单点删除（被 undo 引用的 rescue 拒删）、「立即 GC」。
- **状态诊断**（GET `/shadow-rewind/status`）：最近 20 条错误（相邻重复合并计数 + 环境分类 hint）、后端健康度；POST `{op:'clear'}` 清空。
- **核验方法**：浏览器直接访问 `http://127.0.0.1:<port>/shadow-rewind/status`。

## 8. 端到端核验剧本（建议按序执行）

1. **准备**：新建会话，工作区放 `a.txt`（v1）。
2. **捕获**：让 AI 用 edit 把 `a.txt` 改成 v2，再用终端命令 `echo v3 > a.txt`（终端写盘）。
3. **live 条**：输入框上方出现「已更改 1 个文件」，净 +/- 与 diff 浮层正确（两轮改动都可见）。
4. **行内撤销**：点 ↶ → 文件回到 v3 之前（该文件的检查点净变化被撤）；再点 ↺ → 回到 v3。
5. **回退**：点该消息旁 ↶ → 预览列出将被改动的文件 → 「就地回退」→ 文件回到轮起状态、该消息及之后对话行隐藏、文本回到输入框。
6. **撤销恢复**：恢复后点「撤销本次恢复」→ 文件回到恢复前状态。
7. **检查点缺失**：设置 `turnCheckpointMode: 'off'` 并重启，重复 5 → 对话框如实提示「没有保存这条消息发送之前的文件」，绝不悄悄用另一套恢复集合。
8. **pending**：回合运行中连发两条消息 → 气泡上点撤回 → 确认 → 气泡消失、文本回填。
9. **审查界面**：live 条「审查」→ 逐轮 diff 展开、hunk 撤销、与 live 条状态双向同步。
